# redops — Red Team Campaign Manager + OPSEC Validator
## Implementation Plan · 2026-06-04

### Overview

CLI + SDK + REST API for structured red team engagement management.
Authorized-use-only framing: no C2, no implants, no exploit delivery — management layer only.

**Stack:** Python 3.10, FastAPI, SQLite/SQLAlchemy async, Typer, Rich, Jinja2, WeasyPrint (PDF), python-docx (DOCX), httpx.

**Layout:** `src/redops/` (hatchling src layout), `tests/`, `templates/`, `Dockerfile`, `docker-compose.yml`, `.github/workflows/ci.yml`.

---

### Architecture

```
Campaign Layer
  ├── Engagement (scope, targets, RoE, timeline, operators)
  ├── Objective tree (primary/secondary, completion tracking)
  ├── TTP Planner (MITRE ATT&CK technique selection per phase)
  └── Operator log (timestamped structured entries)

OPSEC Validation Engine (checks YOUR OWN infra, never targets)
  ├── Domain reputation (VirusTotal free API, URLVoid)
  ├── CT log exposure (crt.sh — is your C2 cert already indexed?)
  ├── SSL validity + expiry check (ssl/socket)
  ├── Email infra (SPF/DKIM/DMARC via DNS lookups)
  ├── Redirector health (HTTP chain validation)
  └── OPSEC scorecard (pass/warn/fail + remediation notes)

Report Generator
  ├── Executive summary (objectives + findings)
  ├── Technical narrative (chronological from operator log)
  ├── MITRE ATT&CK coverage table (techniques exercised)
  ├── Detection gap analysis (what blue missed)
  └── Output: JSON, HTML (dark-theme), PDF (WeasyPrint), DOCX (python-docx)

REST API (FastAPI)
  ├── /engagements CRUD
  ├── /engagements/{id}/objectives CRUD
  ├── /engagements/{id}/ttps  CRUD
  ├── /engagements/{id}/log   POST entries, GET timeline
  ├── /engagements/{id}/opsec run checks, get scorecard
  └── /engagements/{id}/report generate (json|html|pdf|docx)

CLI (Typer)
  ├── redops engagement create/list/show
  ├── redops objective add/complete
  ├── redops ttp add/list
  ├── redops log add/show
  ├── redops opsec run <domain>
  └── redops report generate --format html|pdf|docx|json

SDK
  └── redops.RedOps: engagement(), opsec(), report()
```

### Models

```python
# Engagement
class Engagement(BaseModel):
    id: str  # uuid
    name: str
    client: str
    scope: list[str]          # in-scope targets
    out_of_scope: list[str]
    rules_of_engagement: str
    start_date: date
    end_date: date
    operators: list[str]
    status: Literal["planning", "active", "completed", "cancelled"]
    created_at: datetime

# Objective
class Objective(BaseModel):
    id: str
    engagement_id: str
    title: str
    description: str
    type: Literal["primary", "secondary"]
    status: Literal["pending", "achieved", "failed", "partial"]
    completed_at: datetime | None

# TTP (MITRE ATT&CK technique)
class TTP(BaseModel):
    id: str
    engagement_id: str
    technique_id: str     # e.g. T1566.001
    technique_name: str
    tactic: str           # e.g. Initial Access
    phase: str            # e.g. "Week 1 - Phishing"
    status: Literal["planned", "executed", "detected", "blocked"]
    notes: str

# LogEntry
class LogEntry(BaseModel):
    id: str
    engagement_id: str
    timestamp: datetime
    operator: str
    action: str
    technique_id: str | None
    target: str
    result: Literal["success", "failure", "partial", "unknown"]
    notes: str
    evidence_refs: list[str]   # filenames only, not content

# OpsecCheck
class OpsecResult(BaseModel):
    domain: str
    timestamp: datetime
    checks: list[OpsecCheckResult]
    score: int            # 0-100
    grade: Literal["A", "B", "C", "D", "F"]

class OpsecCheckResult(BaseModel):
    name: str
    status: Literal["pass", "warn", "fail", "skip"]
    detail: str
    remediation: str
```

### OPSEC Checks Detail

| Check | Method | Pass Condition |
|-------|--------|----------------|
| `domain_age` | WHOIS via `python-whois` | Domain > 30 days old |
| `vt_reputation` | VirusTotal `/domain/{domain}` free API | 0 malicious votes |
| `ct_exposure` | crt.sh `?q={domain}&output=json` | No unexpected certs (operator confirms) |
| `ssl_validity` | `ssl.create_default_context()` socket connect | Valid cert, ≥14 days to expiry |
| `spf_record` | DNS TXT lookup | SPF record exists |
| `dkim_record` | DNS TXT `default._domainkey.{domain}` | DKIM record exists |
| `dmarc_record` | DNS TXT `_dmarc.{domain}` | DMARC record with `p=reject` or `p=quarantine` |
| `http_redirect` | httpx HEAD chain | 301/302 resolves, no 5xx |
| `open_ports` | socket connect to common ports (80, 443, 8080, 8443) | Only expected ports respond |

Score: each check worth ~11 pts. Grade: A≥90, B≥75, C≥60, D≥45, F<45.

### MITRE ATT&CK Integration

Pull technique list from MITRE's publicly available JSON (no TAXII auth needed):
`https://raw.githubusercontent.com/mitre/cti/master/enterprise-attack/enterprise-attack.json`

Cache locally at `~/.redops/mitre_cache.json` (refresh if >7 days old).

Provide:
- `mitre.search(query)` → list of techniques matching name/ID
- `mitre.get(technique_id)` → technique name, tactic, description
- `mitre.tactics()` → list of all tactic names

## Task 2 — OPSEC Validation Engine

**Goal:** 9-check OPSEC engine with scoring and grading.

**Deliverables:**
- `src/redops/opsec/checks.py` — 9 check functions (async), each returns `OpsecCheckResult`
- `src/redops/opsec/engine.py` — `OpsecEngine.run(domain) -> OpsecResult`, runs all checks, computes score/grade
- `tests/test_opsec.py` — ≥25 tests: each check individually mocked, scoring math, grade thresholds, full engine run mocked

**Checks to implement:**
1. `check_domain_age` — `python-whois`, skip gracefully if whois fails
2. `check_vt_reputation` — httpx GET `https://www.virustotal.com/api/v3/domains/{domain}` with header `x-apikey: {vt_key}`, skip if no key
3. `check_ct_exposure` — crt.sh query, return list of found certs as detail (operator reads output)
4. `check_ssl_validity` — socket+ssl, check expiry date
5. `check_spf` — dnspython TXT lookup
6. `check_dkim` — dnspython TXT `default._domainkey.{domain}`
7. `check_dmarc` — dnspython TXT `_dmarc.{domain}`, check policy
8. `check_http_redirect` — httpx follow_redirects HEAD, verify chain ends 200
9. `check_open_ports` — asyncio.open_connection to [80,443,8080,8443], report unexpected open ports

**Scoring:** each check 11 pts (9 checks = 99 pts max, round to 100). Grade A≥90/B≥75/C≥60/D≥45/F<45.
**Skip checks:** if dependency missing or API key not provided → status="skip", contributes 0 pts (don't penalize).
